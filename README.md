# 连通域标记（从 0 实现）

仓库里只有规格与素材：若干网格文件、对应的期望结果、一份现场记录。程序要新写。

## 1. 范围

交付一个位于仓库根目录的单文件程序 `regionmark.py`（Python 3.13，只用标准库，不加依赖、不加构建步骤）：

```
python3 regionmark.py <网格文件> <输出 html 路径>
```

它读取一份网格，做四连通标记，把编号图和统计表内联到一份可离线打开的单文件 HTML 里。输出路径的父目录不存在时自行创建；参数个数不对、文件不存在或内容非法时，向 stderr 打印一行以 `error:` 开头的说明，以退出码 2 结束，并且不写输出文件。

明确不做的事：

- 不做八连通，也不提供 `--connectivity` 之类的开关；
- 输入只有 0/1 两种取值，不做灰度、阈值、去噪、缩放；
- 不填孔洞，不给背景编号，不按面积过滤或合并区域；
- 不做配色渲染、交互、导出、网络请求；
- 不引第三方库、不引外部资源（CDN、字体、图片、`fetch`）。

## 2. 口径与公式

- 网格是 H 行 × W 列，取值 0（白、背景）或 1（黑、前景）。
- 连通口径：四连通。上下或左右相邻（一个下标相差 1、另一个相同）的两个前景像素连通；对角相接不算。图像之外一律视为背景，不参与连通——两块前景即使都贴着同一条边、甚至各占一个角，只要图内没有上下左右的通路，就是两个区域。
- 编号次序：行优先扫描（自上而下，行内自左向右），遇到还没有编号的前景像素就分配下一个编号，编号从 1 开始连续递增；背景恒为 0。等价说法：一个区域的编号，等于该区域里“最上、同高则最左”的像素在行优先扫描中出现的序号。
- 区域统计（每个区域一条）：
  - 像素数 N：区域内前景像素的个数；
  - 包围盒：该区域行下标的最小值、列下标的最小值、行下标的最大值、列下标的最大值；
  - 质心：行下标之和、列下标之和分别除以 N，按 `format(x, ".4f")` 输出，固定 4 位小数。
- 行、列下标都从 0 开始。

## 3. 数据结构

- 编号图：与网格同尺寸的整数矩阵，0 表示背景，正整数表示区域编号。
- 区域表：按编号升序，每个区域一条记录 `label pixels min_row min_col max_row max_col centroid_row centroid_col`。
- 内部怎么标记不限（栈、队列、并查集都行），但最终编号必须严格符合上面的口径。

## 4. 输入与输出格式

输入（网格文件，UTF-8 文本）：

- 首行 `W H`：列数、行数，十进制整数，空白分隔，且 1 ≤ W, H ≤ 2048；
- 随后恰好 H 行，每行恰好 W 个字符，只允许 `0` 和 `1`；每行首尾空白忽略，行内不得出现空白；
- 文件末尾允许空行；尺寸超限、出现其它字符、行数或行宽不符都算非法输入。

输出（单文件 HTML，UTF-8）必须包含两个数据块：

- `<pre id="label-map">…</pre>`：H 行，每行 W 个编号，单个空格分隔，行尾不留空格；
- `<pre id="stats">…</pre>`：首行为表头 `label pixels min_row min_col max_row max_col centroid_row centroid_col`，其后按编号升序每区域一行，字段单个空格分隔。

两个数据块以外的页面样式不限（内联即可），但不得引用任何外部资源。输出建议放 `var/`，它已被 `.gitignore` 忽略。

## 5. 性能与验收口径

预算（Python 3.13 标准库，同一台机器上测量）：

- 规模上限 2048 × 2048（约 419 万像素），超限按非法输入处理；
- 耗时：基准 A（2048×2048 全 1）与基准 B（2048×2048，偶数列全 1、奇数列全 0）单次运行均不超过 5 秒；
- 内存：峰值 RSS 不超过 256 MiB；
- 不得依赖 Python 递归深度（默认上限 1000）：基准 A 必须正常跑完，不得出现栈溢出或 RecursionError。

验收：

1. 逐个样例运行 `python3 regionmark.py samples/grids/<name>.txt var/<name>.html`，退出码必须为 0；
2. 取出 `<pre id="label-map">` 与 `</pre>` 之间的文本，忽略首尾空行、去掉每行两端空白后，与 `samples/expected/<name>.labels.txt` 逐行一致；
3. `stats` 块同样处理后，与 `samples/expected/<name>.stats.txt` 逐行一致（含表头，顺序敏感）；
4. 生成的 HTML 不含任何外部资源引用；
5. 基准 A、B 的耗时与内存都在预算内。

## 6. 样例说明

| 网格 | 场景 | 看点 |
| --- | --- | --- |
| `samples/grids/ring.txt` | 空心环 | 环是一个区域，环内孔洞是背景 |
| `samples/grids/diagonal.txt` | 对角相接 | 只靠对角串起来的像素仍是多个区域 |
| `samples/grids/border.txt` | 边界相接 | 各贴一边或一角、图内互不相通的四块 |
| `samples/grids/thin.txt` | 细长条 | 1 像素宽的横条、竖条与孤立像素 |
| `samples/grids/fragments.txt` | 大量小碎块 | 48 个互不相邻的小块 |
| `samples/grids/solid_black.txt` | 整片同值 | 全 1，整张图一个区域 |
| `samples/grids/solid_white.txt` | 整片同值 | 全 0，零个区域 |

每组网格对应 `samples/expected/<同名>.labels.txt`（期望编号图，0 表示背景）与 `<同名>.stats.txt`（期望统计表）。`samples/notes.md` 是当初引起争议的现场记录。

## 7. 辅助脚本与测试

- `python3 tools/check_samples.py`：自动比对（第 5 节第 1–4 步），逐个样例运行并核对编号图、统计表与外部资源引用；
- `python3 tools/bench.py`：生成基准 A、B（2048×2048）并以子进程计时、测峰值 RSS；
- `python3 -m unittest discover -s tests`：单元测试（解析、口径、样例逐值、CLI 行为、输出确定性）；
- 页面按编号着色（黄金角配色），面积不足全图 0.1% 的碎块自动淡化，下方列出像素数最多的 10 个区域；着色与统计均来自引擎内联进 HTML 的输出，页面内不重新计数。
